## LongCat-2.5 正式上线：多模态与长程工程任务进入同一接口
**事件日期：2026-11-02；状态：正式上线；能力及算力表现属于厂商宣称，未经本报告独立复测。**

**事实。**官方 API 更新日志于11月2日列出 LongCat-2.5，9月25日的版本则明确标为 Preview。此次属于正式服务更新，不能把两次发布混为一谈。更新重点包括图像理解与代码任务结合、复杂代码库与完整项目的多步执行，以及兼容 Claude Code、Codex、Hermes 等 Harness。Harness 指围绕模型组织工具、执行循环和任务状态的运行框架。官方中文发布页同时称模型总参数1.6万亿、全流程训练采用国产算力。[1][2]

**实质变化。**开发者获得了一个可通过现有工具体系评估的正式模型候选。原生多模态指模型直接处理图像与文字，潜在用途是从界面截图理解问题，再进入代码修改与工具执行。长程任务则强调多轮操作后的整体完成质量。两者结合，比单次问答分数更接近真实 Agent 工作；但“支持完整项目”不等于任意仓库都能稳定交付，兼容框架也不等于所有参数和工具语义完全一致。

**分析。**对 Agent 开发者，价值在于增加可比较的模型供给，而非立即迁移。多步骤流程会放大失败重试、上下文累积和外部工具耗时，因此仅比较参数量或单次 token 单价，容易误判实际成本。评估应固定仓库、工具权限、任务输入和验收测试，同时记录成功率、总费用、总耗时、人工介入次数及回归问题。国产训练链路的意义是基础设施路线增加选择；它不能直接证明某种芯片更便宜，也不能推出当前服务的延迟与稳定性优势。

**开发影响与行动。**可把截图驱动修复、跨文件修改、工具异常恢复作为后续小规模验证的代表场景。接入前需核对正式模型标识、图像输入限制、工具调用格式、计费和数据条款。此次未调用模型 API，也未独立核验价格变化或权重下载状态，不能将“正式 API”写成“权重已开源”。**预测：**若其长程任务能力在相同条件下复现，才可能降低某些工程任务的人工接管成本，目前仍需实测。
